# ExcelVerticalTab VSTO 解説書

この文書は、今回の作業で出てきた `VSTO`、`発行`、`署名`、`setup.exe` などが何者なのかを、後から自分で追えるように整理したメモです。  
「言われるがまま進めたけれど、実際には何が起きていたのか」を把握するための解説書として書いています。

## 1. VSTO とは何か

`VSTO` は `Visual Studio Tools for Office` の略です。  
Office アプリに対して、Visual Studio から `.NET` 製のアドインを作るための仕組みです。

今回のプロジェクトでは、`Excel` に対して次のような機能を追加しています。

- シート一覧を縦タブとして表示する
- シート切り替えをしやすくする
- フィルタやドラッグアンドドロップを提供する

つまり、これは「Excel の外にある別アプリ」ではなく、**Excel の中に読み込まれる拡張機能**です。

## 2. このプロジェクトの正体

このリポジトリは、大きく 2 つの部品でできています。

- `ExcelVerticalTab`
  Excel に読み込まれる VSTO アドイン本体です。
- `VerticalTabControl`
  画面表示を担当する WPF コントロール ライブラリです。

役割分担はこうです。

- `ExcelVerticalTab` が Excel と会話する
- `VerticalTabControl` が UI を描画する

## 3. Build で何が起きているか

Visual Studio で `Debug` や `Release` をビルドすると、まずアドイン本体がコンパイルされます。

主に生成されるものは次です。

- `ExcelVerticalTab.dll`
  アドイン本体です。
- `VerticalTabControl.dll`
  UI 部品です。
- `ExcelVerticalTab.dll.manifest`
  アドインの説明書です。
- `ExcelVerticalTab.vsto`
  VSTO 用の配置マニフェストです。

この時点では、**配布用の材料ができた**だけです。  
まだ「Excel に正式にインストールされた状態」ではありません。

## 4. なぜ Build しただけでは Excel に出ないのか

VSTO アドインは、`dll` を置くだけでは動きません。  
Excel 側には「このアドインを起動時に読み込んでよい」という登録情報が必要です。

そのため、次の要素がそろって初めて動きます。

- アドイン本体の `dll`
- `manifest` と `vsto`
- Excel / Office 側のアドイン登録
- 必要なランタイム
- 署名情報

今回、`Release` ビルド後に Excel を起動してもアドインが出なかったのは、**まだインストール処理をしていなかったから**です。

## 5. Publish で何が起きているか

`発行 (Publish)` は、配布用パッケージを作る作業です。

ここで主に行われることは次です。

- 配布先フォルダーを決める
- マニフェストに署名する
- `setup.exe` を作る
- `ExcelVerticalTab.vsto` を配布用に整える
- 依存ファイルを配置する

Build と Publish の違いはこう考えると分かりやすいです。

- `Build`
  開発者向け。動く部品を作る。
- `Publish`
  利用者向け。インストールできる形に包む。

## 6. 今回生成されたものの意味

今回の流れで重要だったファイルは次です。

- `ExcelVerticalTab.dll`
  実際のアドインの処理本体
- `ExcelVerticalTab.dll.manifest`
  アドインの内容を示すマニフェスト
- `ExcelVerticalTab.vsto`
  VSTO が配布と起動に使う配置情報
- `setup.exe`
  利用者が実行するインストーラー

役割を一言でまとめるとこうです。

- `dll`
  中身
- `manifest`
  説明書
- `.vsto`
  VSTO 用の起動・配置情報
- `setup.exe`
  インストールを担当する入口

## 7. setup.exe を実行すると何が起きるか

`setup.exe` を実行すると、ClickOnce / VSTO の仕組みを使って、アドインを使える状態に近づけます。

典型的には次が行われます。

- 必要ファイルの配置
- マニフェストの検証
- 署名の確認
- VSTO 用の登録
- Excel が読み込める状態へのセットアップ

その結果、Excel 起動時にアドインが候補として読み込まれるようになります。

## 8. 署名とは何だったのか

署名は、配布物に付ける「発行者の身分証」です。

VSTO / ClickOnce では、配布物が誰のものかを示すために、証明書で `manifest` を署名します。  
これが無いと、配布物として信用させにくくなります。

今回のキーワードは次の 4 つでした。

- `証明書`
  発行者の身分証
- `pfx`
  証明書をファイル化したもの
- `証明書ストア`
  Windows の中の証明書保管場所
- `manifest`
  配布物の説明書

## 9. 今回の署名エラーの正体

今回 `Release` で止まった理由は、コードのバグではなく、**署名用証明書をうまく使えなかった**からです。

起きていたことはこうです。

- `Debug` は開発用なので署名なしでも動かしやすい
- `Release` は配布を前提にしているので署名を要求しやすい
- 既存の一時証明書は、MSBuild からの利用で問題が出た
- そのため、Windows の証明書ストアにテスト用コード署名証明書を作って使う形に切り替えた

つまり、署名エラーは「プログラムが壊れている」ではなく、**配布用の身分証チェックで止まっていた**という意味です。

## 10. 今回こちらで何を設定したか

今回の作業では、主に次を整えています。

### プロジェクト設定

- `Debug` は署名なし
- `Release` は署名あり
- `Release` は証明書ストア上のテスト証明書を使う
- 発行先の既定値を整理
- 配布ガイドを追加

### Windows 側の設定

- 現在のユーザーの証明書ストア `CurrentUser\My` に、テスト用コード署名証明書を作成

このため、Visual Studio の画面を細かく触っていなくても、`csproj` を通じて設定が反映される部分があります。

## 11. 今回「できた」と言える状態

今回の時点で確認できているのは次です。

- `Debug` で起動できた
- `Release` ビルドが通った
- `Publish` が成功した
- `setup.exe` を作成できた
- インストールまで進められた

これはつまり、**自分の PC で使うための配布テストはかなり前進した**ということです。

## 12. まだ残っていること

ただし、これはまだ「正式な商用配布」や「他人向けの完成版配布」とは少し違います。

残っているテーマは次です。

- 正式なコード署名証明書への置き換え
- 他 PC でのインストール確認
- 更新手順の固定
- アンインストール手順の確認
- 必要に応じたセキュリティ説明

## 13. 今後また迷いやすいポイント

次に似た場面で迷いやすいのはここです。

- `Build` しただけで使えるわけではない
- `Release` は署名が関係する
- `Publish` すると配布用パッケージができる
- Excel に表示されないときは、インストール未完了か COM アドイン登録を疑う

## 14. 一言でまとめると

今回やっていたことを一言でいうと、

**Excel 用の .NET アドインを、配布可能な VSTO / ClickOnce パッケージとして整え、署名付きでインストールできる状態にした**

ということです。
